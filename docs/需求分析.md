# JSON Harbor：需求分析与首版范围

## 用户与任务

面向开发者、测试与接口联调人员。主任务：粘贴接口返回值或配置 → 看清结构与错误 → 进行必要转换或对比 → 复制 / 下载结果。

“使用频率高”是针对这类目标用户的产品假设，目前没有访谈或留存数据；通过上线后的真实任务反馈验证。

## 同类观察与切入点

[JSONEditor](https://github.com/josdejong/jsoneditor) 与 [svelte-jsoneditor](https://github.com/josdejong/svelte-jsoneditor) 已覆盖成熟的树、代码编辑、查询、修复和校验场景；不以“功能最多”作为首版目标。

[lossless-json](https://github.com/josdejong/lossless-json) 的文档展示了原生 JSON.parse / JSON.stringify 在长整数、大指数和小数原文上的变化风险。本项目选择保留 AST 中的数字与字符串字面量、有序对象成员，避免格式化时重新编码数值。这是具体切入点，不声称首创或已验证增长。

## 五组首版需求

| 需求 | 首版行为 | 主要验收 |
| --- | --- | --- |
| 看清 JSON | 格式化、压缩、递归键排序 | 保留 19 位 ID、2.370、-0；排序不改变数组顺序 |
| 找到错误 | 严格语法校验、行列与定位 | 无效转义、尾逗号、缺少逗号有明确错误 |
| 浏览与提取 | 懒加载树、搜索、JSON Pointer | 路径转义正确，提取长数字不舍入 |
| 比较文档 | 字段级新增 / 删除 / 修改 | 忽略对象顺序，数组按下标；报告截断有说明 |
| 随时使用 | 本地网页、主题、导入导出、CLI / API / Skill | 公网可用，程序入口实测，数据不持久化 |

重复键格式化时保留并警示；路径经过重复键、或结构对比任一文档含重复键时拒绝猜测。错误输入保持原文，不自动“修复”。

## 明确边界

不做账号、云存储、远程 JSON URL 拉取、AI 自动修复、完整 JSONPath、Schema 校验及各种格式互转。限制 2 MiB、128 层和 50000 节点，以清楚的失败信息替代未经验证的大文件承诺。

## 为什么适合小工具系列

价值可以直接演示：输入长 ID → 格式化仍保持每一位 → 提取路径 → 展示差异。复用来自接口联调和配置编辑，而不是一次性视觉玩法。发布后先观察用户能否独立完成任务、是否在后续联调中再次使用，以及对比规则是否符合实际需要。
